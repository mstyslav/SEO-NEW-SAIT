# Space Glass — Sprint 20

## Виправлено картку товару
- мініатюри переміщені ліворуч від великого фото;
- zoom зроблено маленькою круглою кнопкою;
- великі фото перегенеровано з найбільшого локального джерела у високій якості;
- прибрані фільтри, що могли погіршувати різкість.

## Документація
- універсальні фейкові PDF прибрано;
- показуються лише документи, прив’язані до конкретної моделі;
- створено оригінальні матеріали Space Glass:
  - схема заміру Walk-in;
  - інструкція з догляду за склом;
- монтажна інструкція не показується, доки не погоджено конкретну систему та фурнітуру.

## Статуси товарів
- базовий статус усіх товарів: «Під замовлення»;
- можна окремо додавати позначки:
  - ТОП продажу;
  - Хіт продажу;
- статуси та позначки зберігаються у `src/data/products.json`.

## Каталог
- усі картки автоматично показують «Під замовлення»;
- ТОП/ХІТ виводяться лише для зазначених товарів.


## Sprint 21
- у Mega Menu рядок «Пошук за містами» вирівняно по одній горизонтальній лінії з назвами міст;
- прибрано завищення заголовка;
- усі елементи мають однакову висоту та вертикальне центрування.


## Sprint 22
- у Mega Menu велике фото тепер реально змінюється залежно від категорії;
- для різних категорій призначені різні чіткі зображення;
- у блоці «Сумісні товари» рівно 4 картки в одному рядку;
- додані фотографії, категорії та необов’язкові позначки ТОП/ХІТ;
- розпочато наступний етап плану — конфігуратор товару;
- додані ширина, висота та вибір «тільки виріб / з монтажем»;
- підсумок конфігурації оновлюється автоматично.


## Sprint 23 — функціональний конфігуратор
Додано:

- колір профілю;

- товщину скла;

Формула є попередньою та призначена для UX-прототипу. Фінальну бізнес-формулу потрібно погодити окремо.


## Sprint 24 — система «Отримати КП»

### Mega Menu
- для кожної основної категорії підготовлене окреме велике зображення;
- зображення експортуються у 1800×2100 px з високою якістю;
- усі зображення попередньо завантажуються;
- прибрані blur-фільтри під час перемикання.

### Картки товарів
- позначки «ТОП» і «ХІТ» зменшені;
- розташовані у правому верхньому куті;
- якщо позначки немає, місце не резервується.

### Комерційна пропозиція
Нова сторінка:
`/quote/`

Вона отримує з конфігуратора:
- назву товару;
- усі вибрані параметри;
- попередню ціну;
- фото товару;
- артикул.

Додано:
- форму контактних даних;
- завантаження фото та креслень;
- збереження чернетки форми в браузері;
- підготовку структури заявки для майбутньої CRM;
- повідомлення про успішне формування заявки.

Поки це frontend-прототип. Реальне надсилання email/CRM потребує backend або інтеграції форми.

## Sprint 31 — header/form corrections + Kommo preparation

### Виправлено за останнім скріном
- хедер зміщено вправо на 10 мм;
- усі елементи хедера залишаються в одному рядку;
- іконки не змінювались;
- кнопка «Отримати розрахунок» стала компактнішою;
- форма має три однакові поля у першому рядку:
  Ім’я / Телефон / Місто;
- четверте поле «Що потрібно» має таку саму ширину;
- зайве поле «Додатково» не створювалося;
- замість нього у другому рядку розташована кнопка.

### Наступний крок
Підготовлено безпечний серверний endpoint:
`POST /api/kommo-lead`

Додано структуру payload для передачі в Kommo:
- контакт;
- телефон;
- email;
- місто;
- мова;
- товар;
- конфігурація;
- попередня ціна;
- склад проєкту;
- UTM-мітки.

Реальне підключення потребує серверних даних Kommo:
- subdomain;
- access token;
- pipeline ID;
- stage/status ID;
- ID custom fields.

Токен Kommo не можна зберігати у frontend-коді.
